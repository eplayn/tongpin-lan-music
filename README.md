# 同频 C 1.1.3 — Windows 局域网音频共享


源码：[eplayn/tongpin-lan-music](https://github.com/eplayn/tongpin-lan-music) · [下载发布版](https://github.com/eplayn/tongpin-lan-music/releases/latest)

当前主分支为 Windows 原生 C 版。此前的 Node.js 3.2.3 保留在 [`node-v3.2.3`](https://github.com/eplayn/tongpin-lan-music/tree/node-v3.2.3) 标签和 Git 历史中。C 版使用独立的 `c-v1.1.3` 版本标签。

打开 `LanSync.exe`，程序自动把系统默认声音送到 VB-CABLE，统一安排本机和浏览器的播放时间。本机继续通过原来的扬声器/耳机发声，其他人使用浏览器收听。

Windows 主程序使用 C 编写，不需要 Node、Python、.NET 或 Electron。音频入口使用第三方 VB-CABLE；浏览器端使用随程序内嵌的 HTML/JavaScript Web Audio 接收页。

## 直接使用

1. 解压到可写文件夹，双击 `LanSync.exe`。如果已经安装 VB-CABLE，无需重装。
2. 在这台电脑播放音乐。通常不必手动更改系统输出，程序会自动切换并在退出时恢复。
3. 将窗口显示的**局域网地址**发给同一个局域网中的其他设备，例如 `http://192.168.1.100:17890/`，无需口令或其他参数。
4. 对方用浏览器打开地址，点“开始收听”。其他设备不要使用 `127.0.0.1` 地址。
5. 保持 Windows 程序运行。关闭窗口后停止共享，并恢复原来的三个默认音频角色。
6. 在窗口“固定缓冲”中输入毫秒数，**按 Enter** 或点击“应用并保存”。默认 **600 ms**，允许 **50–5000 ms**。修改后本机和浏览器重新缓冲，收听地址不变，无需重新打开页面。设置保存在 EXE 旁的 `lansync.ini`，下次启动继续使用。

主机网页仅监测，不再重复播放，避免浏览器声音进入 CABLE 形成回声。其他设备可以正常播放。本机实际输出设备是启动前的真实默认扬声器或耳机；如需更换，请退出程序，先在 Windows 中选好输出，再重新打开。

### 在另一台 Windows 首次使用

- 如果没有 VB-CABLE，点“安装 VB-CABLE”打开官方下载页。程序和压缩包均不携带驱动安装包；首次需要联网从官网下载，解压后由你确认管理员权限、阅读条款并完成安装，然后按官方要求重启 Windows，再打开同频 C。已经安装的电脑无需重复下载。
- 不需要开启测试模式、关闭安全启动、导入测试证书，或安装之前自研的实验驱动。
- 若其他设备打不开网页，点“允许局域网”。这会在你确认管理员权限后添加**当前程序、专用网络、本地子网、TCP 17890**的入站规则。移动 EXE 到其他目录后，程序路径改变，可能需要重新授权。
- 路由器的访客网络/AP 隔离可能阻止设备互访。多网卡电脑请选择与接收设备同网段的地址。

## 同步、延迟与恢复

- 共同缓冲为手动固定值，网络报告、掉线和加入新听众均不会改变它。默认 600 ms；可逐步调低并实听。如果发生卡顿，手动调高。50 ms 是允许输入的下限，不是所有设备均能达到的稳定延迟；实际采集、网络、浏览器和硬件都有开销，不能保证零延迟。
- 所有音频包携带相同的采集时间和目标播放时间。本机通过 WASAPI 时钟播放；浏览器优先使用输出时间戳映射。
- **本机和浏览器始终原速播放**，没有变速追赶。数据不及时就补静音或停顿，恢复后丢弃迟到片段并回到统一时间，不积压旧声音。这意味着卡顿时可能缺失一小段声音。
- 本机另用真实输出回环被动比对播放内容，估计设备实际流水线偏差。需要纠正时直接插入静音或跳过部分样本，绝不拉伸音频；不会修改手动缓冲值，也不会额外播放校准提示音。需要有可辨识的音频；纯静音或单频音会等待有效信号。
- 手动修改缓冲是一次重新缓冲，可能短暂停顿。不是渐变变速。所有新音频包的时长始终为原始帧数除以 48 kHz。
- 听众独立重连；网络恢复后加入当前声音，不补播旧声音，不暂停其他人。
- 本机监测页的“播放诊断与校准”显示回环校准状态。接收设备的同名面板提供音量和当前设备的时间微调。
- 正常退出和主进程异常终止都会尝试恢复原来的默认输出。程序修改前先写恢复记录并启动独立守护进程；会尊重用户后来主动选择的其他设备。

浏览器报告的输出时间不是声学测量。蓝牙耳机、功放、电视音效和部分驱动的额外延迟可能无法被浏览器准确报告，需要通过接收页的校准滑块结合实听微调。手机后台/锁屏播放由系统与浏览器控制，系统冻结页面时可能中断；回到页面后会重新同步或提示继续播放。

## 当前验证范围

验证平台：本机 Windows 10 x64、已安装的微软硬件兼容发布者签名 VB-CABLE、Realtek 真实扬声器。

- 自动选择标准 CABLE Input，实际加载的 VB-CABLE 驱动状态和签名验证通过。
- 独立 C 音频应用经 Windows 默认设备发声；实际 CABLE 采集、原生物理输出及 HTTP/WebSocket 的 7 项检查通过。
- 被动校准使用真实输出回环测量。当前版本的测量结果见 `verification.json`，这是本机回环时序结果，**不代表跨设备声学同步误差**。
- 正常退出、强制结束主进程后，原来的三个默认音频角色已验证能恢复。
- 手动增减缓冲、5000 ms 接收队列、设置保存与重启恢复、迟到处理及原速播放有自动检查。持续传输结果、实际计数和测量限制见发布包的 `verification.json`（源码中为 `tests/verification.json`）。

跨物理设备的最终实听测试按约定由用户进行，尚不能宣称所有网络、浏览器和硬件都已验证。原始 PCM 带宽约每位听众 1.536 Mbit/s，不含协议开销。程序最多接收 32 个听众连接，这不是 32 台设备的已验证容量保证。

## 使用边界

目标平台为 Windows 10/11 x64，普通用户运行主程序；首次安装 VB-CABLE或设置防火墙需要管理员授权。此包未验证其他 CPU 架构。

只保证进入 Windows 系统默认共享输出的音频。固定绑定其他设备、ASIO/独占输出和受保护内容可能无法采集；旧应用可能需要重开音频流或改回“系统默认设备”。标准双声道 CABLE Input 优先，避免误选 16 声道端点。

默认 TCP 端口为 17890，当前支持 IPv4。直接打开 `http://主机局域网IP:17890/` 即可，无需口令、查询参数或登录 Cookie。主机 IP 未变时，重启后地址保持相同。局域网内能够访问此端口的人均可收听。传输为 HTTP/WebSocket，适用于可信局域网，没有互联网中继或外部上传。

## 构建与诊断

构建工具：MSYS2 UCRT64 GCC 和 PowerShell；打包及网络测试使用 Python，可选的网页检查使用 Node。编译不需要下载驱动包。这些都是开发工具，运行交付 EXE 不需要它们。

```powershell
.\build.ps1 -Test
.\dist\LanSync.exe --devices
.\dist\LanSync.exe --driver-status
# 仅供诊断；普通使用直接打开 EXE。
.\dist\LanSync.exe --headless --duration 30
.\dist\LanSync.exe --test-tone
.\dist\LanSync.exe --buffer-ms 200
# 已打开窗口时，通过本机命令修改并保存：
.\dist\LanSync.exe --set-buffer-ms 300
.\dist\LanSync.exe --stop
```

`--test-tone` 是独立合成测试音模式，不共享真实系统声音。正常使用不要加此参数。`--buffer-ms` 仅覆盖本次启动的值；窗口应用或 `--set-buffer-ms` 才保存。`--set-buffer-ms` 和 `--stop` 用于已打开的窗口，不控制无窗口诊断实例。`--source`、`--output` 和 `--no-route` 保留作开发诊断；自动运行不需要设备索引。

源码：`src/audio.c` 采集/播放，`src/calibrate.c` 本机被动回环校准，`src/sync.c` 统一时间轴，`src/server.c` 原生 HTTP/WebSocket，`src/route.c` 路由恢复，`src/cable.c` 官方下载入口与驱动状态检查，`web/` 浏览器接收页。
